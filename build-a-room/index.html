Room integration guide

Bring your architecture into Locus.

Model, texture, light, and export with the professional tools you already know. Locus does not prescribe an authoring workflow; it consumes one USDZ plus a small, explicit interface for openings, seats, surfaces, and optional lights.

The delivery contract

Deliver one flat ZIP with exactly five root files:

my-room.zip
├── space.json
├── provenance.json
├── teleport-points.json
├── scene.usdz
└── thumbnail.jpg
  • scene.usdz is self-contained, meter-scale, +Y up, and uses world -Z as forward.
  • space.json describes the Room. It has a display name but no authored asset ID.
  • teleport-points.json declares at least one usable seat.
  • provenance.json truthfully records creator, rights, credit, changes, and AI use.
  • thumbnail.jpg is authored with the Room; Locus does not generate it during import.

Keep editable sources, textures, caches, and interchange files outside the ZIP. Every entity referenced by metadata must have one stable, unique name in the delivered USDZ.

Openings and seats

Every Room declares exactly one viewOpenings entry. It is the framed connection between the architecture and the selected Locus View. Coordinates use right-handed meters, +Y up, -Z forward, and quaternions in [x, y, z, w] order.

Each teleport point defines an eye position and facing direction. anchorXZ is normalized into the exported Room bounds; sourceFloorOffset identifies its level; eyeHeight is measured from that floor. Seat IDs are part of the Room interface, so keep them stable across revisions.

Author for use, not just preview. Import the exact ZIP and enter every seat on Apple Vision Pro. A structurally valid Room can still have an uncomfortable eye height, blocked view, wrong scale, or poor clearance.

Optional spatial adaptation

spatialAdaptation connects semantic parts of your USDZ to Locus features:

FieldContract
wallEntitiesUnique exported entities Locus may adapt for Room Portal.
roofEntitiesUnique exported roof or ceiling entities Locus may adapt.
deskEntitiesByTeleportIDMaps a seat ID to the exact entity for its tabletop surface.

A mapped desk entity should be the tabletop itself or a tightly bounded slab. Do not include chairs, lamps, legs, computers, or loose props beneath it; Locus uses the entity's bounds to derive surface height, footprint, and orientation.

Optional lighting interface

Lighting metadata tells Locus which exported emissive meshes and bounded runtime sources belong to each visitor-facing control. It does not prescribe how to model, shade, or bake the Room.

FieldLocus behavior
luminaireGroupsOne group is one logical switch and one set of brightness/color controls.
entitiesNames the emissive fixture bodies. An enabled fixture remains visibly emissive from every seat.
proxy / proxiesDeclares bounded point or spot sources. Use proxies in Room v3 when one switch drives multiple physical emitters.
nearTeleportIDsLimits only the direct proxy sources to selected seats; it does not hide or darken the fixture body elsewhere.
bakedIndirect.entitiesRoom v3 receiver subtrees for low-frequency indirect light controlled by the Room Lights master and Overall Room EV.

The shared indirect layer is scaled by 2^overallEV. Individual light switches, temperature, color, and brightness remain local controls and do not recolor that shared bounce. Keep glass, water, transmissive materials, fixture glow meshes, and recognizable fixture-specific halos out of the shared indirect receiver subtree; direct proxies own local pools of light.

Room v3 enforces a maximum of 12 authored proxies, 4 active proxies at any seat, 1 shadow-casting proxy, 10,000 lumens per proxy, and a brightness range within -4…+1 EV. These are safety limits, not target values.

Lighting is optional. Omit lighting for a Room without visitor-controlled fixtures. Use Room v2 for basic light groups, or Room v3 for multiple proxies and Room-owned baked indirect light.

Pack, validate, then import

Keep the five source files in one directory and run the public tools on macOS:

python3 tools/pack_locus_asset.py /absolute/path/to/room /absolute/path/to/my-room.zip
python3 tools/validate_locus_asset.py /absolute/path/to/my-room.zip
  1. Resolve every warning or error from the USDZ exporter and public validator.
  2. In Locus, choose Import a Room and select the exact validated ZIP.
  3. Pair the Room with a View and enter it on Apple Vision Pro.
  4. Try every seat, optional desk mapping, Room Portal surface, and light control you declared.
  5. Correct the source and rebuild the ZIP; do not patch the final archive by hand.

Build with an AI assistant

Give the public sample skill to an AI coding agent that can use a professional 3D authoring tool. Starting with your brief, it can create an original Room, connect seats and optional lights to the Locus interface, scaffold the five delivery files, validate the exact ZIP, and guide the final in-app check. The skill stays out of tool-specific modeling technique, so experienced creators can keep their own workflow and judgment.

If an agent cannot operate a suitable 3D tool, the skill tells it to say so before promising a finished Room.
