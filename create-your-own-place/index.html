Complete Package v2 import is available in Locus 1.2.1 and later. The 4K minimum for directly imported panorama images, including Browser images, is separate from either ZIP format. Complete packages preserve stable IDs and update semantics. Flat compatibility ZIPs and direct panorama images receive a new UUID on every import.

Remove an imported package

Open an import’s menu and choose Remove Import. Removing an import always removes that whole package. When a package contains more than one Room or View, the confirmation lists them.

If another installed package depends on this package, Locus leaves both packages unchanged. Remove the dependent package first. Otherwise, Locus removes its installed package files and saved package content; your original ZIP or image in Files or cloud storage is unchanged. Importing the original package again creates or updates it under its stable identity and counts its Views and Rooms toward your current import allowance.

Package Views and Rooms separately when they need independent lifecycles. Combined Package v2 archives remain supported, but Remove Import removes every View and Room that the combined archive contains together.

Recommended complete Package v2

complete-place.zip
├── locusplace.json
└── catalog/
    ├── destinations/<destination-id>/destination.json
    ├── spaces/<space-id>/space.json
    └── experiences/<experience-id>/experience.json   # optional

Put locusplace.json and catalog/ directly at the ZIP root—never inside an outer wrapper folder. Content assets stay under their matching destination, space, or Experience directory. Locus accepts the same ZIP bytes with a .zip or .locusplace filename.

To share a View and Room together, include both in one complete package. Add an experience.json when you want to author that pair’s opening, orientation, exposure, title, or supported mode. The Experience refers to the View and Room by stable ID; without it, Locus derives its default pairings. Import the combined file once through Places → Import → Import a View or Import a Room, using Files or a direct public HTTPS URL. The entrypoint must match content in the package; the combined contents install together. See the complete-package guide and example for the manifests and packing commands.

This format preserves authored stable IDs, View media and masks, sourceImage, View-owned USDZ midground scenery and renderer-owned water, View and Room sound, Room animations, video surfaces and seat groups, provenance, and supported bundled Experiences. Its manifest declares packageID, contentVersion, minimumAppVersion, content IDs, file hashes and sizes, and contentHash. Locus validates the exact inventory, safe paths, hashes, resource limits, capabilities, and minimum app version. A malformed complete package is rejected rather than retried as a flat ZIP.

The package is data, not code. In the same Locus binary, supported Room and View data works the same when bundled, downloaded from the Library, or imported from a complete public ZIP. Source may affect entitlement, updates, storage, removal, and labels; it does not unlock renderer features. Packages cannot include scripts, plugins, dynamic libraries, or executable extensions. Read the security boundary and future-extension rule.
Legacy/simple Room ZIP layout
my-room.zip
├── space.json
├── provenance.json
├── teleport-points.json
├── scene.usdz
├── thumbnail.jpg
├── sound.json         # optional, Locus 1.1.4
└── forest-air.m4a     # one or more, only with sound.json

In this compatibility format, all five files are required at the ZIP root. space.json contains displayName; it does not contain an asset ID, and each import receives a new UUID. Do not add a parent folder, editable source, GLB, source textures, or any other file. Locus does not generate a thumbnail when one is missing. A Room may also carry its own sound: add sound.json and its audio files at the root, described in the format reference. Every audio file must be named by a source in sound.json, and audio without it is rejected.

Legacy/simple View ZIP layout
my-view.zip
├── view.json
├── provenance.json
├── panorama.jpg
├── thumbnail.jpg
├── lighting.jpg       # optional
├── sound.json         # optional, Locus 1.1.4
└── waterfall.m4a      # one or more, only with sound.json

The panorama must be a complete 2:1 equirectangular image. A packaged View can set starting direction, brightness, contrast, saturation, ambient-light intensity, horizon pitch, and optional sunlight in view.json. A user can change these later with Edit View. A View may also carry its own sound on the same terms as a Room, described in the format reference.

Provenance

Every Room and View needs provenance.json. Record the creator or agency, rights, requested credit, changes, and AI use truthfully. Supply exactly one of license or rights, as described in the format reference. When aiGenerated is true, include aiProvider; when false, omit it. The license describes rights in the asset; an App Store EULA is not an asset license. See Locus asset rights for Locus-authored examples.

Pack and validate a compatibility ZIP

For a complete Package v2 archive, use the complete-package guide and its pack_locusplace.py / validate_locusplace.py tools. The commands below remain for the legacy/simple flat format only. Keep the five Room files or four required View files in one directory. Run the included tools on macOS:

python3 tools/pack_locus_asset.py /absolute/path/to/asset /absolute/path/to/asset.zip
python3 tools/validate_locus_asset.py /absolute/path/to/asset.zip

The Room validator uses Xcode's usdchecker. A valid result checks the archive and machine-readable assets; it does not replace importing the exact ZIP and trying every seat.
