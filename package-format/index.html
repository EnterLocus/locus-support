Technical reference

The Room package format is inspectable by design.

The supported Room transport envelope, authorable Package-v2 fields, schemas, tiny reproducible examples, packer, and validator are published together.

Current import boundary. Views enter Locus directly as one 2:1 JPEG, PNG, or HEIC image. This archive reference applies to Import a Room: the archive must contain a Room and may include its paired View and Experience. It is not a whole-catalog import API.

Supported Room examples

These examples contain generated 16 × 8 PNG data, a tiny structural USDZ, strict provenance, Package-v2 manifests, and canonical integrity fields. They contain no private room, paid provider output, account data, or proprietary launch media.

Room-only packageOne Room with a self-contained USDZ; import it with Import a Room.Room with a paired ViewOne Room, one View, and their explicit Virtual Space Experience; import the bundle with Import a Room.

The source builder also emits a View-only archive as a validator fixture. The current app does not expose a View-package import action, so use a direct image for a custom View.

Authority and licensing boundary

The shipping Locus importer is the installation authority. The public validator is intended to catch authoring and CI failures before import, but a future app version can enforce additional compatibility or platform checks.

Publishing these documentation and tool files does not publish the private Locus app source, disclose its implementation, or state that the application has adopted an open-source license.
